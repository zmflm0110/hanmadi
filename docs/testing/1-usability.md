# 1단계: 일반인 사용성 평가

말하기에 어려움이 없는 사람으로 **조작 방식** 자체를 먼저 검증한다. AAC 사용자의 실제 효과는 3단계에서 본다.

## 질문

- 문법 도움을 켜면, 같은 뜻을 전하는 데 드는 **시간**과 **누름 수**가 줄어드는가?
- 문법 도움을 켜면, 만들어진 말이 **더 자연스럽게** 들리는가?
- 처음 쓰는 사람이 설명 없이 쓸 수 있는가? (SUS 68점 이상이면 평균 이상)

## 참가자

- 10~20명. 중학생 이상, 한국어 모국어 화자. 참가자 코드는 번갈아 준다(P01, P02, …).
- 이 앱을 처음 쓰는 사람. 만든 사람과 친한 정도는 적어 두기만 한다.

## 준비

- 태블릿(없으면 노트북), 앱 최신판, 소리 켜기.
- 시작 전에 설정 → 기록 지우기.

## 진행(1인당 약 20분)

1. **안내(2분).** 이렇게 읽어 준다: "그림 카드를 눌러 말을 만드는 앱이에요. 화면에 나오는 상황에 맞는 말을 만들어서, 초록색 문장을 누르면 소리로 말해 줘요. 정답은 없고, 앱을 평가하는 거지 당신을 평가하는 게 아니에요."
2. **연습(3분).** 과제에 없는 말 두 개를 만들어 보게 한다. 예: `[나] [빵] [좋다]`, `[물] [주세요]`. 설정의 문법 도움을 켰다 껐다 하며 차이를 보여 준다.
3. **과제(10분).** 설정 → 참가자 코드 입력 → 과제 시작. 12과제 중 앞 6개와 뒤 6개의 조건이 서로 다르다(자동). 진행자는 돕지 않는다. 막히면 "건너뛰기"를 눌러도 된다고만 말한다.
4. **SUS 설문(3분).** [sus-ko.md](sus-ko.md)
5. **짧은 인터뷰(2분).** "제일 불편했던 점은?", "켰을 때와 껐을 때 차이를 느꼈나요?"

## 재는 것 (미리 정함)

| 지표 | 정의 | 출처 |
|---|---|---|
| 과제 성공률 | 과제 뜻이 전달된 비율. 자동 판정은 참고만 하고, 진행자가 만든 문장을 보고 최종 판정 | 기록 `task.match`, `task.text` |
| 과제 시간 | 첫 카드부터 말하기까지(초) | `task.ms` |
| 누름 수 | 카드 추가·삭제·말하기를 모두 센 것 | `task.taps` |
| 후보 순위 | 말한 문장이 몇 번째 후보였나(문법 켬만) | `task.rank` |
| SUS | 0~100 | 설문 |
| 자연스러움 | 아래 "듣는 사람 평가"의 평균(1~5) | 별도 평가 |

**분석:** 참가자마다 조건별 중앙값을 내고, 켬과 끔의 차이를 짝지어 비교한다(윌콕슨 부호순위 검정, `analyze_logs.py`). 표본이 작으니 p값보다 **차이의 크기와 방향**을 먼저 보고한다.

## 듣는 사람 평가 (자연스러움)

과제에서 만든 문장을 모아, 앱을 안 써 본 5명에게 섞어서 보여 준다. 조건 표시는 가린다.

> 이 말을 들었을 때 얼마나 자연스러운 한국어로 들리나요? 1 매우 어색함 ― 5 매우 자연스러움

## 한계

- 일반인은 AAC 사용자와 운동·인지 조건이 다르다. 시간 차이는 3단계에서 그대로 재현되지 않을 수 있다.
- 문법 끔 조건은 "카드 이름 읽기"만 흉내 낸다. 실제 국내 앱과의 비교가 아니다.
